02 · One command

The pipeline runs the example end to end.

Run bash ./run.sh locally or in Ubuntu CI. Compose starts the app and dependencies, waits for health, runs the gates, and cleans up at exit.

ConsumersUse the Smart Mock

JavaScript and Playwright examples validate consumer behavior against a mock served from the shared OAS.

Lint→Build and start→Contract and API tests→Security scans
03 · Contract roles

Provider and consumer checks answer different questions.

Specmatic exercises the provider from its contract. Consumer examples run against a contract-derived Smart Mock, while API integration tests call the live application.

ProviderDoes the app honor the contract?

Specmatic sends contract-derived requests to the healthy application. The WireMock example separately checks the downstream inventory contract.

ConsumerCan clients develop against the agreement?

JavaScript and Playwright use the Specmatic Smart Mock. Their separate integration runs call the provider itself.

The consumer demonstration uses the shared provider OAS as a mock source. It is not a separate consumer-owned CDC contract.
04 · Test behavior

Fuzz independent requests. Sequence stateful workflows.

Stateless fuzzingOne request stands on its own

Schemathesis generates independent Product API requests from OAS, probes boundaries, and validates responses. Each case does not rely on data from earlier cases.

Stateful testingFollow linked operations

The separate Order API preserves state across a lifecycle. OAS links pass the created identifier between operations.

Create→Read→Confirm→Delete→Verify 404

Seven native clients repeat the lifecycle and validate each live response against the stateful OAS.

05 · Native API tests

Keep automation in the language teams maintain.

Each example uses a small API client object for requests and a language-native test framework for behavior and OAS response validation.

Rust · Go · PythonNative HTTP clients

Typed request helpers, test fixtures, lifecycle checks, and contract validators.

JavaScript · TypeScriptCode-based suites

JavaScript test runner and TypeScript test runner validate live provider responses.

Java · C# · PlaywrightFramework-native tests

JUnit and xUnit cover the lifecycle; Playwright APIRequestContext demonstrates provider and consumer tests.

Manual debugging is a separate use case. Swagger UI and Prism provide optional contract-driven views; they do not replace CI automation.
